# 操作原则
- 采用 > 调整 > 发明；保持变更可逆且可观察。
- 里程碑，而非时间线；尽可能使用功能标志/终止开关。

# 简洁工作循环
1) 澄清需求 + 验收标准；快速检查"这是否已存在？"。
2) 简要规划（里程碑；任何新依赖项及理由）。
3) TDD 优先，小型提交；保持边界清晰。
4) 验证（单元 + 目标 e2e）；必要时添加指标/日志。
5) 交付 PR，包含理由、权衡、部署/回滚说明。
